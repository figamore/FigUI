# Robot Studio

A full-screen FluidUI / FigUI plugin for modeling, teaching, planning, and controlling a six-revolute-joint arm. Install this folder with **Plugins → Add**, or copy it to `/sd/plugins/robot-studio/` and refresh the plugin list. It is also registered in the repository's plugin store.

## FigUI compatibility

Update FigUI and Robot Studio together for guarded SD starts, browser program streaming, automatic browser workspace storage, and session recovery. Older FigUI hosts can jog through `sendCommand` when the acknowledged `sendJog` API is unavailable. The workspace also runs as a standalone simulator when served over HTTP. See the [FigUI plugin API guide](../PLUGIN_GUIDE.md#api).

FigUI restores the controller-session workspace first, then the browser copy, then the project saved on the controller. Browser copies are scoped to the controller address and carry workspace data only. Use **Save project** to write to the controller and **Export JSON** to make a separate backup. After a reload, record a new manual reference. After a connection interruption, you can also verify a recovery candidate when one is available.

Leaving the browser tab or another client taking control pauses local control. Returning requests fresh feedback. Use **Live joints** to resume after a takeover. Reset, firmware homing, alarms, and controller changes invalidate calibration. If the saved project cannot be loaded, wait for Idle and choose **Retry restore**.

## Controller-ramped MoveJ

With **Use controller maximum speed and acceleration** enabled, each moving MoveJ waypoint now exports one `G94 G53 G1` command. Its feed uses the same mapped-joint velocity calculation as jogging. FluidNC supplies acceleration, braking and junction handling, removing the browser's quintic ease-in/ease-out and common sequence stretch from these joint moves. Consecutive MoveJ commands are queued together. Go home and Jog to pose use the same approach in controller-maximum mode.

This changes controller-maximum MoveJ paths to straight joint-space segments between taught poses; preview the regenerated path. The preview shows a trapezoidal/triangular estimate from rest for each segment. Physical motion can finish sooner when firmware lookahead carries speed between waypoints, so its displayed duration is approximate. Gripper commands and stationary waypoints retain their waits, and transitions between controller-ramped joints and sampled paths synchronize before continuing. Custom-limit moves, MoveL and demos retain their existing sampled profiles.

Program speed and the controller feed override still apply. A saved waypoint's minimum time also caps its requested feed, including older waypoints with longer times. Set both speed percentages to 100% and check existing minimum times when comparing with jogging. Firmware axis limits remain in force; no controller configuration is rewritten.

## Joint dragging

Click a solid joint housing in the 3D viewer to select it and place X/Y/Z arrows at its center. The selected joint is highlighted and its J-number stays visible. A click selects; dragging the workcell still orbits. Click the gripper to return to the tool, or use the target selector at the top of Cartesian controls to choose **Tool TCP** or a joint. Turning **Jog TCP** back on also returns to the tool.

Joint dragging changes only the upstream joint angles that can position the selected housing. Its own and downstream joint angles stay unchanged, so the rest of the arm follows naturally; the TCP is allowed to move and rotate. The solver uses the displayed housing center, including its configured offsets. **World frame** uses fixed world axes; **Joint frame** aligns the arrows with the selected joint's local frame. Fixed housings, such as the base, have no translation arrows. Directions that upstream motion cannot affect are hidden, as are arrows pointing straight into the camera.

Some housings can only follow a circle or another curved surface. Hold **Shift** or enable **Push** to follow a nearby reachable point when the exact axis target is unavailable. Joint limits still apply. Selection and dragging change the virtual target; use **Hold to jog** for physical positioning or **Add waypoint** to teach the resulting pose. Joint selection pauses Live joints and is unavailable during motion, program execution or preview.

## Push dragging

Enable **Push** in the viewer toolbar, or hold **Shift** during a TCP arrow drag, to let the tool rotate and move off the requested axis toward a nearby reachable position. This helps when keeping the original orientation prevents a strict axis move. Push finds a local approximation, so the tool may fall short of the pointer at a reach or joint-limit boundary. The Cartesian feedback shows its remaining distance from the requested target. Joint limits still apply, and each update limits joint changes to 6° to keep adjustments local. Push cannot extend the arm beyond its physical reach.

Shift activates Push temporarily; the toggle keeps it enabled across drags. Pressing or releasing Shift also updates an active drag without needing another pointer movement. When Push ends, strict dragging holds the adjusted orientation instead of restoring the original one. In Tool frame the arrows retain their starting directions during the gesture, then align with the adjusted tool on release. Push edits only the virtual target; **Hold to jog** still controls physical positioning.

## Drag the tool

Choose **Jog TCP** above the 3D viewer to open Cartesian controls and show red **X**, green **Y** and blue **Z** arrows at the configured tool center point. Drag an arrow forward or backward to translate the virtual arm along that axis while keeping its tool orientation. **World frame** uses the fixed world axes; **Tool frame** aligns the arrows to the tool at the start of the drag. The handles keep a readable size as you zoom. Drag elsewhere to orbit; an axis pointing directly at the camera is hidden until you orbit to expose it. The existing Cartesian rose and exact inputs also work with a keyboard.

Dragging edits the virtual target. Use **Hold to jog**, beside **Jog TCP** in the toolbar, for calibrated physical positioning, or **Add waypoint** to teach the result. Release the button to cancel motion. Reference setup, **Recover reference** and **Go home** are under **Physical machine connection**; the Move and Program tabs sit directly at the top of the side panel. Jog TCP switches out of Live joints. A target beyond reach, joint limits or solver tolerance keeps the last valid pose and manual reference; from upright home, use **Preview working pose** first if needed. Release, Escape, pointer cancellation, focus loss, switching controls or opening a dialog ends the drag. Handles pause during program execution, playback and other motion operations. Turning Jog TCP off restores ordinary orbiting.

## Reference recovery

After a connection interruption, open **Physical machine connection** and choose **Recover reference**. With the controller Idle, the dialog shows the current joint angles calculated using the previous zero offsets. Verify that these angles match the physical arm and confirm that FluidNC retained its coordinates, with no lost steps or movement with drives disabled. **Recover reference · no motion** restores the existing mapping; the arm does not need to return to the home pose. Choose **Live joints** afterward to resume local control. Previous targets and programs are not replayed.

The recovery copy is retained in FigUI memory across reconnect attempts and closing/reopening Robot Studio, scoped to the controller address and plugin. It is not automatic authorization: a disconnect can hide a controller restart or physical movement. Fresh six-axis Idle feedback, compatible calibration and joint limits are checked before accepting recovery. Known resets, firmware homing, alarms, controller changes and calibration changes remove the candidate. A full FigUI page reload also removes this memory; saved project offsets alone are not treated as a confirmed reference. Update both FigUI and Robot Studio for this feature.

## SD execution

Select **Program → Run from → SD card**, then **Run from SD**. Robot Studio compares the generated program with `/robot-studio.nc` on the SD card. Matching contents run directly without rewriting the file, including after reopening the plugin. Changed or missing contents are saved and read back for verification before running. A failed read, save or verification prevents starting. The source selection is remembered with the project.

**Export & execution details → Save program to SD** performs the same comparison and save without starting motion. Save and Run both require the manual reference and fresh Idle feedback, and use the physical starting pose. Changes to the entry pose, robot mapping, speed, waypoints or gripper commands can change the file. Within the open workspace, the same prepared plan is reused when inputs match and the robot is still within the existing 0.25° start tolerance, so telemetry rounding does not cause repeated uploads.

SD execution lets FluidNC read the motion locally, removing browser scheduling and Wi-Fi delivery from the motion-command supply. It can improve remaining stutter caused by streaming latency; it does not remove intentional stops, motor step quantization or firmware acceleration/junction limits. Browser stream remains available. Go home, Jog to pose and demos continue to stream.

SD progress follows reported joints. Pause/Resume and Stop remain available. File-specific start and completion messages, an end-of-motion synchronization, and fresh final Idle/position feedback distinguish successful completion from an initial Idle report or a prematurely closed job. A lost start response is never retried. Stop during saving prevents starting; Stop after dispatch resets motion and invalidates the manual reference. Connection changes or another client taking control end local job ownership. Update both FigUI and Robot Studio for guarded SD starts and uncached file comparison.

## Smooth waypoint programs

Consecutive moving MoveJ waypoints share velocity and acceleration at their joins. Each joint passes through its exact taught angle and stays within the range between adjacent taught angles. The joint-space path between waypoints can curve to make the transition continuous; preview the newly planned trajectory. A reversing joint slows through zero. Program endpoints, stationary waypoints, gripper-action segments and transitions to MoveL retain stops. MoveL still follows the requested straight TCP path.

Joint moves no longer generate extra samples solely because a long arm sweeps a large TCP distance. Short moves reduce their sample count according to duration while retaining angular resolution and rechecking motion limits. G-code retains five-decimal machine-coordinate precision, omits unchanged axis words after the first motion, and removes redundant decimal zeros. Repeated or sub-resolution samples inside a moving path carry their time into the next motion instead of inserting dwells. A deliberately stationary waypoint produces one dwell. Gripper sequences retain their arrival synchronization and restore a complete axis target on the next move.

Update both Robot Studio and FigUI for the streaming improvement: FigUI now uses a 255-byte outstanding-command window within FluidNC's 256-byte WebSocket receive allowance, while retaining the eight-response limit, acknowledgement ownership, transport backpressure and Pause/Stop behavior. This allows multiple six-axis commands in flight instead of waiting for a network round trip per motion sample. These changes improve streaming headroom; network stalls, controller settings and physical dynamics still affect execution.

## Rose jog controls

Move → Joints now opens a rose pendant inspired by the WebUI jogpad. Two roses are stacked together: the upper rose controls J1/J2 with J3 on its side rail; the lower rose controls J4/J5 with J6. All six joints are available without switching groups. The labels identify robot joints, not Cartesian directions. Each group shows its three joint angles and names.

- **Step:** tap an inner, middle, or outer ring for 0.1°, 1°, or 5°. The side rail has the same signed steps. Target pose changes only the virtual arm. In Live joints, a tap requests one finite joint move from fresh, stationary machine feedback; further steps wait for that move to finish. Out-of-range destinations are rejected.
- **Hold (default):** Live joints and Hold are selected by default when opened in FluidUI. Controls become ready automatically once the reference and fresh Idle feedback are available. Hold a sector or the side rail to jog continuously; release, pointer cancellation, lost capture, or focus loss cancels the jog. Enter/Space can also hold a focused direction; key release cancels. A second pointer cannot take over an active gesture. Changing Step/Hold discards pending motion. Both roses share the selected behavior and allow only one held joint at a time.
- **Stop:** the center button uses the same stop action as the global Stop/Escape control. Exact numeric targets, sliders, and the original hold buttons remain under **Exact angles & sliders**.
- **Cartesian:** the same rose edits Position (X/Y/Z, mm) or Orientation (RX/RY/RZ, degrees) in the selected World or Tool frame. These are virtual IK targets; they do not stream Cartesian motor moves. Cartesian steps use 0.05 mm / 0.05° solver tolerances, below the smallest 0.1-step ring. An unsolved target keeps the previous pose and manual reference; it does not imply calibration was lost. Physical positioning retains the calibrated Hold to jog workflow. Exact world-frame inputs remain under **Exact TCP target**.

Cartesian position steps keep the existing tool orientation. Upright home has a straight elbow and aligned wrist, so some requested directions cannot be reached from that pose with orientation held. For the parallel-elbow layout, **Preview working pose** explicitly bends an aligned elbow by 40° and wrist 2 by 30°, adjusting shoulder and wrist 1 to share the elbow bend. It checks joint limits and changes only the virtual target, including tool orientation. Use **Hold to jog** to reach that working pose before retrying Cartesian steps. The manual reference is retained. This offers a less constrained starting posture; reach and joint limits still apply to every target.

## Gripper control

The 3D model includes a two-finger gripper in the workcell, configuration preview and manual homing view. It follows the configured tool frame and scales with the wrist. Manual Open/Close commands and waypoint previews update the displayed jaw spacing. This shows the last command or preview action, not measured jaw feedback. The attachment is illustrative and does not add a tool offset; configure the actual flange-to-TCP transform for your hardware.

**Move → Open gripper / Close gripper** operates the end effector directly, from either the joint or Cartesian controls. Each button sends its complete sequence in one WebSocket request, without per-line HTTP waits. It finishes any current jog before sending and restores live readiness automatically. The gripper does not require a joint reference.

The default Open sequence is `M67 E0 Q5`, `G4 P0.5`, `M67 E0 Q0`. Close uses `M67 E0 Q10`, `G4 P0.5`, `M67 E0 Q0`. Edit either multiline sequence under **Setup → Gripper commands**, click **Apply gripper commands**, then **Save project** to retain it.

In Program, choose **After next waypoint → Open gripper / Close gripper** before adding a pose, or change **After arrival** on any existing waypoint. The selected sequence runs after reaching that pose and before moving to the next waypoint. For example: approach the object, close at the pickup pose, lift, then open at the drop-off pose. Actions follow their waypoints when reordered and support Undo/Redo.

Run on machine and Export G-code include the configured sequences. Preview displays the gripper action and includes its dwell time without operating the physical output. Gripper dwell time is independent of the program speed override. Project save/export preserves both the command definitions and each waypoint's action; older projects start with no waypoint actions.

- Controller and manual-reference details are under Physical machine connection. The toolbar Hold to jog button explains unavailable motion in its tooltip.
- Program expands the task panel and puts the waypoint list first. Every waypoint has a labeled Delete button; Clear all removes the sequence and supports Undo. New-waypoint defaults, speed settings and demos are collapsed below the list. Add, Plan, Preview and Run remain visible around the scrolling list. On phones, the program actions and Stop remain available while scrolling.
- Waypoint add, delete, rename, reorder, motion, timing, and pose updates support 30 steps of Undo/Redo. Use the toolbar or Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z in Program outside text fields. History clears when a project or configuration is applied; undo never moves the robot.
- Save project reports edits not yet saved to the controller, pending saves, and failures. Only one controller save can be pending, and an older response cannot mark newer edits as saved. Ctrl/Cmd+S saves the project. The browser copy is automatic; controller saving remains explicit. Export downloads a separate backup.
- Open validates JSON before offering to replace the current project. Configuration edits retain waypoints when geometry and travel limits remain compatible; destructive changes show a review dialog with Cancel focused first.
- Joint, Cartesian, and Setup tabs support arrow keys, Home, and End. Numeric validation identifies the field that needs attention.

## Workflows

- **Joint control:** an Arm/Wrist rose pad with step rings and live hold-to-jog, plus exact sliders and numeric angle inputs, enforced joint limits, configured home pose, and synchronization from machine positions.
- **Cartesian control:** world position and roll/pitch/yaw targets; full six-dimensional damped least-squares inverse kinematics with seeded retries, residual reporting, and world/tool frame stepping.
- **3D workcell:** lightweight native cylinders for links and joint housings, with joint rotation markers, driven by the same forward kinematics as the planner, orbit/zoom, front/top/fit views, joint labels, optional coordinate frames, TCP axes, and trajectory display. Three.js and OrbitControls `0.170.0` ship in the local classic-script `viewer-lib.js`, so the viewer needs WebGL but no internet, module imports, or CDN access. This also works in FluidUI’s opaque-origin iframe sandbox.
- **Teaching:** capture, name, recall, update, reorder, and delete up to 200 waypoints. Set MoveJ/MoveL and a minimum duration per point.
- **Planning:** controller-maximum MoveJ uses straight joint-space segments with firmware ramps; custom-limit MoveJ uses quintic joint interpolation with continuous joins. MoveL uses straight TCP translation, shortest-path quaternion interpolation, sequential IK and rejection of unsolved samples or large joint discontinuities. Program speed and waypoint minimum times apply independently. Custom sampled paths enforce joint speed and acceleration limits; stationary waypoints, gripper actions and transitions to/from sampled motion retain stops.
- **Persistence:** Save project writes to FigUI's plugin settings on the controller. Standalone HTTP use saves to browser local storage. JSON export/import includes geometry, limits, axis mapping, base/tool frames, virtual pose, and waypoints. Imports are validated before replacing any current state. Playback, machine enable, and connection state are never persisted.
- **Controller:** live slider jogging or hold-to-move joint jogging through FigUI, G-code export, and single-pass program execution from the browser or SD card, with reported-position visualization, current-waypoint highlighting, position-based progress, Pause/Resume and Stop. Browser streaming does not write a job file; SD execution saves only changed contents.

The entry page waits for its HTML and stylesheet to finish loading, then loads `kinematics.js`, `viewer-lib.js`, `viewer.js`, `live-control.js`, `jog-transport.js`, `program-control.js`, `singularity-demo.js`, `piston-demo.js`, `motion-settings.js`, `jog-pad.js`, and `app.js` sequentially. Some FluidNC devices return transient 404 responses when multiple SD assets are requested concurrently, even though each file is accessible individually. Failed assets are retried up to three times, then the failing URL is shown in the workspace.

The default **Standard arm** is a six-axis example with parallel shoulder, elbow, and first wrist axes. Use its sample dimensions for simulation and enter the measured dimensions of your arm for physical control.

| ----- | -------------------------------------------- |
| J1    | Base rotation                                |
| J2    | Shoulder pitch                               |
| J3    | Elbow pitch, parallel to J2                  |
| J4    | Wrist 1 pitch, parallel to J2/J3             |
| J5    | Wrist 2, perpendicular to J4                 |
| J6    | Wrist 3 / tool rotation, perpendicular to J5 |

**Move → Setup → Configure dimensions & limits** opens a clickable arm diagram. Click a measurement or focus its field to highlight the corresponding dimension. Enter positive physical measurements; the editor converts upper-arm/forearm lengths into negative standard-DH `a2`/`a3` values automatically. Advanced DH fields stay synchronized with the diagram fields.

| Measurement | Standard arm | Meaning                                      |
| ----------- | ------------------ | -------------------------------------------- |
| d1          | 150 mm           | Base plane to shoulder axis height           |
| a2          | 600 mm             | Shoulder to elbow rotation-axis distance     |
| a3          | 550 mm           | Elbow to wrist 1 rotation-axis distance      |
| d4          | 160 mm         | Shoulder-to-wrist plane offset               |
| d5          | 110 mm           | Wrist 1 to wrist 3 axis offset along wrist 2 |
| d6          | 90 mm            | Wrist 2 axis to flange offset along wrist 3  |

Tool extension is zero by default and is configured separately. The viewer uses native Three.js cylinders for a simplified six-axis arm, with rounded link junctions, beveled housings, colored joint caps and off-center rotation markers. Housings sit on the solver’s joint axes; link tubes follow the configured lengths and offsets. The parallel-elbow display uses d4 to space the shoulder and first wrist housings sideways from the elbow. These housing positions are illustrative; d4 remains the DH offset along the wrist 1 axis in the motion calculations. Base/tool frames, custom dimensions and other DH layouts use the same procedural renderer. This is a pose visualization, not an exact robot envelope. Jogging and programs use controller maximum speeds by default. The configured 10°/s and 20°/s² preset values remain available as custom limits; they do not cap controller-maximum mode. FluidNC controls jog acceleration and braking; programs also enforce their planned joint acceleration limits.

Standard, Extended, Medium, Compact, and the legacy forearm-roll presets are available in the configuration editor. Select one and click **Load selected preset**, then **Apply configuration**. Existing saved/imported projects retain their original geometry and mapping. Changing geometry or introducing limits incompatible with taught points asks before clearing the program. Compatible name, mapping, home, and motion-limit edits retain taught points. Applying configuration retains the manual reference when joint axes, scales, zeros, angle offsets and home angles are unchanged. Export your project before changing its arrangement if you need to retain it.

The workspace uses FigUI’s theme and keeps a large 3D viewer beside one task panel. **Add waypoint** is available in both Move and Program; the Program toolbar stays visible while scrolling. It remains visible but disabled during execution. Capture and Update use the displayed target pose or fresh, stationary machine feedback. **Recall pose** opens Move for editing, and Target pose switches the display back to the virtual arm. **Joint move** and **Linear move** in the program editor correspond to MoveJ and MoveL. **Move** contains joints, Cartesian controls and setup; **Program** captures and edits waypoints, plans paths and plays previews. On phones, the viewer stays above the task panel.

Each waypoint also has **Jog to pose**, which physically moves from the current reported position to that waypoint in one joint move. It uses the program speed and controller limits, requires a confirmed manual reference and fresh controller feedback, and provides the same Pause/Stop controls as Go home. The destination ghost remains visible, and the selected waypoint is highlighted. It preserves the waypoint list and does not run the waypoint's gripper action or its Linear move path; use Run on machine for those programmed actions. Recall pose remains a virtual preview.

Setup → Configure dimensions & limits accepts:

| Parameter           | Meaning                                                  |
| ------------------- | -------------------------------------------------------- |
| a, d                | Standard DH link length and offset, mm                   |
| α, Offset           | Standard DH link twist and joint angle offset, degrees   |
| Min, Max, Home      | Joint travel limits and virtual home pose, degrees       |
| Max °/s, Max °/s²   | Joint velocity and acceleration limits                   |
| Base → world        | World transform of the robot base                        |
| Tool → flange       | Tool frame expressed relative to the last DH flange      |
| Axis, Units/°, Zero | Mapping from joint angle to a FluidNC machine coordinate |

The transform for each joint is `Rz(q + offset) · Tz(d) · Tx(a) · Rx(alpha)`. Base and tool orientation use `Rz(rz) · Ry(ry) · Rx(rx)`, with translations in mm and angles in degrees. TCP readouts and targets are expressed in the world frame. Euler angles are not unique near pitch ±90°; the solver uses rotation matrices/quaternions internally.

Applying configuration pauses machine control. Dimensions, base/tool frames, appearance, travel limits and speed edits preserve joint calibration. Changing joint axes, scales, zeros, angle offsets or home angles requires a new manual reference. Compatible edits retain the program and target pose; incompatible geometry or travel limits require confirmation before clearing taught points and returning to the configured home pose. Export the current project first if you need to retain it.

## Physical robot setup

Robot Studio uses independent FluidNC joint axes. Configure FluidNC with Cartesian firmware kinematics and six independent motor axes X/Y/Z/A/B/C. Do not combine the plugin's kinematics with another firmware arm transform.

For each joint: `machine_position = angle_degrees × scale + zero`. A negative scale reverses direction. Set motor calibration, homing, machine-coordinate zero, travel limits, firmware speed limits, and firmware acceleration limits to match the hardware. Firmware speed/acceleration limits remain essential; browser timing cannot enforce servo dynamics. **Go home**, beside the controller status above Move and Program, physically returns all six joints to their configured Home angles in one joint move. It uses the program speed settings and the existing Run/Pause/Stop execution path, preserving taught waypoints and gripper state. **Preview home** only moves the virtual model. Use the manual reference workflow below to establish the physical joint reference.

The cycloidal project generator uses 20:1 reduction for J1–J5 and direct drive (1:1) for J6. It calculates `units_per_degree = direction × motor_steps_per_rev × microsteps × ratio / (360 × FluidNC_steps_per_mm)`. Motor resolution, driver microsteps and controller steps per unit must be supplied; the NEMA frame size alone does not determine them. A controller already calibrated in joint degrees uses scale 1 (or −1 for reversed direction). Existing saved/imported projects retain their mapping and are not automatically divided by 20.

For this arm's direct-drive J6, the motor is 1.8° per full step (200 steps/revolution) with 1/8 microstepping. Set the mapped FluidNC axis (C by default) to `steps_per_mm: 4.444444`, calculated as `200 × 8 / 360`. That makes each controller unit one joint degree, despite FluidNC's linear-axis setting name. Robot Studio presets default to J6 **Units / °** `1`. For an existing project, choose **Setup → Configure dimensions & limits → FluidNC machine axis mapping → Use J6 direct-drive default**, then apply configuration. This changes only J6's scale to `1` (or `-1`, retaining reversed direction). Resolution is 0.225° per microstep. Save the controller configuration and robot project, and re-establish the manual reference after changing the coordinate scale. The supplied previous value, `106.666667`, is 24 times this direct-drive steps-per-degree value.

### Manual homing without sensors

1. Enter the real geometry, travel limits, axis scales/directions and each joint’s reference angle in **Setup → Configure dimensions & limits**. The preset reference is `J1=0°, J2=−90°, J3=0°, J4=−90°, J5=0°, J6=0°`: upper arm and forearm straight upright, wrist vertical, and tool flange pointing horizontally outward along the shoulder axis. Saved projects retain their reference angles; select **Use upright homing pose** in the manual homing dialog to change just those six angles, preserving dimensions, limits, mapping and taught points. This checks the configured joint limits and requires a new physical confirmation. Save project after confirming to retain the change.
2. Open **Manual homing** in Setup or **Physical machine connection → Set manual home reference**. The dialog shows the exact configured pose in an orbitable 3D view and lists all six angles.
3. Physically place the robot in that pose, using repeatable marks or fixtures. Keep it stationary. Click **Confirm pose & record reference** only when every physical joint matches its displayed reference angle.
4. Recording requires fresh Idle telemetry with all six finite machine positions. The plugin calculates each `zero = current_machine_position − home_angle × scale`. This writes only the in-memory model mapping: it sends no motor move, `$H`, coordinate-setting command, or alarm unlock. **Save project** persists the offsets.
5. Return to **Move → Joints** to jog with the default **Live joints / Hold** controls, or choose **Target pose** for virtual positioning. Confirmation is retained for the current controller connection. With FigUI’s session bridge, reopening the plugin restores the reference for the same joint calibration and makes live controls ready automatically once fresh Idle feedback arrives. Brief telemetry delays, virtual IK failures and client takeover retain calibration. Client takeover requires selecting Live joints again; it does not require manual homing. A controller reconnect, reset, alarm, firmware homing, importing a project or changing joint calibration invalidates the reference. Reloading FigUI also starts a new session. Older FigUI versions retain the reference only while the plugin stays open. Repeat after controller restart, lost steps or moving the arm with drives disabled. The browser cannot independently detect all of these events.

This establishes the plugin’s physical joint reference, not firmware homing state. If your controller requires a homed state, configure FluidNC for your sensorless/manual commissioning workflow separately; this plugin does not bypass that requirement.

Machine enable requires a confirmed manual reference, all six finite positions within the model limits, an Idle state, and a status event received within two seconds. Hold to jog sends one absolute `$J=G53 G90 G21 ... F...` command. Release, pointer cancellation, focus loss, hidden document, stale telemetry, or Stop/Escape cancels the active jog with real-time byte `0x85`. A delayed send response after release triggers another cancel. Controller errors disable the mapping. The move is joint-space regardless of which control tab produced the virtual target.

### Live joint control and position feedback

**Move → Joints** defaults to **Live joints / Hold**. If a reference is needed, choose **Set reference** or **Live joints** to show the configured home pose; place the arm in that pose and click **Confirm pose & enable live controls**. This records the reference and enables live controls together. No arming checkbox is required in this workflow, and activation itself sends no move.

- **Hold** is selected by default. Hold a rose sector or side-rail button to jog continuously. The **− / +** buttons under Exact angles & sliders also support holding. Release to cancel that jog; live mode stays enabled for the next joint. Pointer cancellation, losing focus and keyboard release also cancel the jog.
- Drag a joint’s slider or enter an angle to move directly to that target. An unchanged target uses one continuous, single-axis absolute jog at the configured joint velocity multiplied by Jog speed. Firmware handles acceleration and deceleration. Same-direction extensions can blend into the moving path; shorter targets, reversals and switching joints cancel the old path and wait for fresh Idle telemetry before restarting.
- Jog speed, Set reference and Stop are beside the live-mode button. **Stop / Escape** cancels the current motion and clears its destination; Live joints and Hold remain selected for the next gesture. **Target pose** switches both roses to virtual Step controls and stays selected until you choose Live joints again. Returning to Live joints restores the previous Step/Hold choice.

The solid 3D arm and TCP readouts follow FluidNC telemetry. Each joint row shows its reported angle below the target slider. A transparent orange arm, including the gripper, shows the requested destination pose and disappears when the reported joints reach it. **Hold to jog** automatically follows the reported arm while keeping the destination as a ghost. **Go home**, running or paused programs, and previews show the current segment's destination; the ghost advances with each segment. **Position display → Show reported machine position** also enables this comparison before moving. Fit includes both poses. The mode badge shows **Virtual**, **Machine ready**, or **Live joints**.

The sender uses WebSocket jog commands and permits at most two collinear endpoints in the planner. With the newer `sendJog` bridge it waits for each controller acknowledgement and pauses background queries that also produce acknowledgements, while keeping realtime status polling active. On older FluidUI builds, `sendCommand` confirms only that the bridge queued the command; the plugin serializes these requests and uses reported joint progress and controller-error events to track motion. The older bridge cannot reserve the acknowledgement channel. It does not wait for Idle between these continuous moves. Held jog buttons stream finite endpoints with two seconds of nominal travel each, within the joint limits, and cancel the entire path on release. Slider and numeric destinations move to the explicitly selected angle. Controller errors, invalid feedback, stale telemetry or a joint that stops making progress stop live control. The controller’s configured speed and acceleration limits still apply. Network delay and firmware braking affect stopping response.

Live jogging does not use HTTP, which FluidNC can reject while moving. Starting a program automatically suspends live control and releases the reserved command channel before streaming. Stop or retarget discards any compatibility fallback that has not yet been dispatched, and closing the plugin cancels its jog.

Leaving the joint tab, switching to Program, changing configuration, losing window focus or hiding the page cancels live motion and clears pending destinations. The Live joints selection and Step/Hold choice are retained. Returning to the focused joint panel automatically restores live readiness once the reference and fresh Idle feedback are available; it never replays a destination. Brief telemetry gaps also restore readiness when feedback returns. Explicitly selecting Target pose or disabling machine control opts out of automatic live readiness. Changing speed retains live mode and replans at the new rate. A late “Jog cancelled” response from a released or replaced destination keeps live mode enabled and waits for fresh Idle before the next move. Unexpected cancellation, controller errors and acknowledgement timeouts still stop live control and require choosing Live joints again after resolving the fault. Re-enabling requires fresh Idle telemetry and does not replay the previous target.

FluidNC positions are tracked motor coordinates. On this arm without joint encoders, they do not independently measure joint position or detect lost steps. Re-establish the manual reference if the physical arm and displayed position disagree. Machine-follow and mode choices are not saved in projects; opening a connected plugin starts with Live joints / Hold selected. Standalone use starts in Target pose. If communications fail, the browser cannot guarantee delivery of jog cancel; the controller can finish already accepted motion. Use the physical stop when needed.

### Program speed, acceleration and execution

Controller limits are read at startup and by **Refresh controller limits** or **Use controller maximums**, outside the Run path. FluidUI imports all six axes' runtime acceleration settings as well as maximum rates. If controller settings change while Robot Studio is open, refresh them before planning again. The controller-limits **ⓘ** shows both speed and acceleration for each mapped joint and labels configured fallbacks. Update FluidUI and Robot Studio together for the host acceleration import. No firmware limits are changed.

Maximum-mode MoveJ uses the reported velocity limits and firmware acceleration, without a browser-generated slow ramp. Waypoint minimum times, joint synchronization, and required waits for gripper actions or stationary waypoints remain. Custom sampled MoveJ blending uses a common time stretch when needed to keep a sequence within its joint limits; MoveL also retains its sampled timing constraints.

**Use controller maximums** is available in Move and Program. It reads FluidUI’s machine settings, including all six axis maximum feedrates and acceleration limits. On older FluidUI builds, it reads the runtime `[ESP400]` tree while Idle. Values follow the configured axis mapping: joint speed is `max_rate / (60 × abs(units/degree))`, acceleration is `axis_acceleration / abs(units/degree)`. No controller configuration is written. Missing or invalid axis maximum rates use a 1200 units/min fallback (20°/s when units/degree is 1); reported rates take precedence. If acceleration is unavailable, the existing configured joint acceleration is retained. Fallback values are labeled in the displayed limits. The button applies those limits and sets the selected panel to 100%; Program also selects the fastest feasible demo cycle. It resets the controller feed override to 100%. Save project keeps the imported joint limits.

Move defaults to **100% Jog speed** with **Use controller maximum jog speeds** enabled. This applies to live joint jogs and Hold to jog, including Cartesian targets. Disable that option under Joint limits & controller settings to edit the custom maximum joint speed. The choice is saved independently from the program speed mode. Hold to jog requests a constant feed constrained by each moving joint's speed limit; it does not reduce that feed using an extra browser acceleration estimate or impose a 0.1-second minimum move time. FluidNC performs acceleration, deceleration and short-move limiting. Known controller limits cap jog commands and planned trajectories. The bottom viewer bar shows actual controller feedrate and feed override during jogging and programs, with a dash for missing or stale telemetry. Feedrate is in mapped axis units/min, not Cartesian TCP speed. During a running program, Speed −10% and Speed 100% adjust the controller override without restarting the job.

Program defaults to controller maximum speed and acceleration at 100% program speed. This also applies when opening older projects with lower configured jog limits. Under Speed, uncheck Use controller maximum speed and acceleration to use custom joint limits; the Max joint speed and Joint acceleration fields then edit the same per-joint limits as Setup. The maximum-speed choice is saved with the project. Program speed is independent of the Move panel's jog override, and speed scaling does not also scale acceleration. Waypoint times are minimum durations; new waypoints and demo cycles default to 0.1 s, while saved waypoint times remain editable.

Preview starts at the first taught waypoint and runs once. **Run on machine / Run from SD** instead plans an entry move from the current reported physical pose, then visits every taught waypoint once. It requires the manual reference and fresh Idle telemetry with no other controller file open. If a reference is missing, it opens manual homing with **Confirm pose & run program**. Both modes stop jogging and release the jog channel. Browser mode starts the acknowledged WebSocket sender without writing a file. SD mode compares, saves if needed, verifies and starts the SD file. The host checks starting joint positions again before dispatch. There is no automatic fallback between modes.

The Run button and edits stay locked during stream preparation and execution. Preview always starts at the first waypoint, even after a physical run with an entry move. A second Run request is rejected. Each plugin can pause, resume or stop only its own stream. Status updates track execution and never restart it. An ambiguous start is cancelled rather than retried. Completion requires both sender completion and a fresh Idle report at the final joint pose. Closing the plugin aborts its stream. Keep the browser connection open while streaming; a disconnect stops sending and does not replay queued moves after reconnecting.

The solid robot follows reported machine positions. The current waypoint is highlighted; percentage progress is estimated by matching all six reported joint angles to the planned path, rather than treating the controller's file-read percentage as executed motion. Pause sends feed hold; Resume continues that same job. Stop / Escape aborts the controller program with a soft reset and requires a new manual reference. Closing the plugin requests an abort. Firmware axis rate and acceleration limits still cap real movement; raising plugin limits alone cannot raise lower FluidNC limits.

### Motion demos

**Program → Motion demos** offers two finite programs without teaching waypoints. Both preserve taught points and return to the starting joint pose. Preview and Export G-code use the displayed demo; Plan path and Run on machine return to the taught program.

- **Singularity crossing.** Choose **Red X**, **Green Y**, or **Blue Z**, and a sweep of 5–80° each side (35° by default). The arm moves to a working pose that aligns the wrist-2 rotation axis with the selected **world** direction. Wrist 2 then crosses a multiple of 180°, where wrist 1 and wrist 3 axes become parallel, and crosses back. The reference triad marks the crossing pose. The tool follows an arc, rather than remaining pinned. The selector changes the spatial direction of the crossing; all three choices demonstrate the same wrist-alignment singularity. Joint-space interpolation keeps the planned branch continuous through alignment instead of asking IK to choose a branch there. This requires a parallel-elbow layout and enough configured joint travel.
- **Piston:** two straight, 30 mm strokes by default, holding tool orientation steady. Horizontal X is the default; Horizontal Y and Vertical Z are also available in world coordinates. Horizontal strokes move in the positive axis direction and back; vertical strokes move down and back. A near-straight elbow first bends into a working pose to leave room for the stroke. Setup and restoration are labeled joint moves. Stroke samples and their joint-linear interpolation are checked against 0.05 mm line error and 0.05° orientation error. Unreachable or discontinuous strokes are rejected; reduce the stroke or start from a different pose.

**Tool extension · flange Z** defaults to **30 mm** for a project with no tool offset. Starting either demo applies the selected extension to the shared model and viewer, retaining taught joint poses and the manual reference. Save project retains the new offset. Existing nonzero tool transforms retain their extension, lateral offsets and orientation. The colored shaft shows the configured tool. Use the actual flange-to-tip offset for a physical tool; full XYZ and orientation settings remain under **Setup → Configure dimensions & limits → Tool → flange**.

In FluidUI, demo buttons use the same single-pass WebSocket streaming path as waypoint programs, with manual reference, Pause/Resume, Stop and reported arm feedback. Standalone use animates a preview. The **Demo minimum cycle** applies to the crossing/stroke sequence, with setup and restoration time added separately. Joint speed and acceleration limits can extend the duration. Use 0.1 s to let those limits determine the shortest planned cycle.

Exported programs use `G21`, `G90`, `G53` on every move, and `G93` inverse-time feed on sampled joint segments, then restore `G94`. Deliberately stationary waypoints become dwells; duplicate samples inside motion are coalesced with their time preserved. The starting joint pose is documented in the `START REQUIRED` comment. **Position the physical robot at that starting pose before running the file.** Export G-code only downloads a file. Run uses the selected browser or SD mode. Go home always streams. Firmware acceleration, quantization, feed overrides, and buffering may increase actual time or change sampled speed profiles relative to the preview.

## Scope

This provides robot-style teaching and kinematic planning, not a safety-certified industrial controller. It does not perform collision detection, obstacle avoidance, payload/gravity compensation, torque control, singularity-proof global planning, calibrated vendor protocols, or safety-rated emergency stopping. Numerical IK can fail for reachable targets; change the seed, add an intermediate point, or use MoveJ. Never infer collision clearance from a successful plan. Stop/cancel is a software jog cancellation; use the physical emergency stop for emergencies.
